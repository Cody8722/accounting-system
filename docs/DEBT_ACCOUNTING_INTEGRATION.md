# 欠款與記帳整合功能規格書

> **版本 1.0** ｜ 由 `accounting-integration-spec.docx` 轉錄為 Markdown 保存。
> 本文所述功能後端多已實作，保留作為設計脈絡與整合邏輯參考。

## 一、背景與目的

現有系統已具備「記帳」與「欠款追蹤」兩個功能模組，但兩者原本完全獨立運作，統計數據無法互通。本規格書定義三項整合功能，使系統能夠反映使用者的真實財務狀況。

| 問題 | 說明 |
|------|------|
| 現有問題 1 | 統計頁面的「餘額」只計算記帳收支，未納入欠款，導致淨資產顯示不正確 |
| 現有問題 2 | 還款操作只更新欠款狀態，未同步產生現金流記錄，造成收支帳目遺漏 |
| 現有問題 3 | 群組分帳的「未收金額」無法被統計層讀取，導致整合計算時需額外處理 |

---

## 二、功能一：整合統計 API

### 2.1 功能說明

新增一個統計端點，同時讀取「記帳記錄」與「欠款記錄」兩個資料表，合併計算後回傳完整的財務概覽。前端儀表板使用此端點取得所有統計數字。

### 2.2 端點規格

| 欄位 | 說明 |
|------|------|
| 路徑 | `GET /admin/api/stats/overview` |
| 需要登入 | 是（與現有端點相同） |
| 快取策略 | 5 分鐘 TTL，與現有統計端點一致；寫入任何記錄時清除快取 |

### 2.3 回傳資料結構

端點回傳以下 JSON 欄位：

| 欄位名稱 | 說明 |
|----------|------|
| `cash_balance` | 現金餘額 = 總收入 − 總支出（僅計算記帳記錄） |
| `receivable` | 應收金額 = 所有未結清 `lent` 欠款的剩餘未還金額加總 |
| `payable` | 應付金額 = 所有未結清 `borrowed` 欠款的剩餘未還金額加總 |
| `group_receivable` | 群組應收 = 所有未結清 `group` 欠款中，成員尚未付款的份額加總 |
| `net_balance` | 淨餘額 = `cash_balance + receivable + group_receivable − payable` |
| `lent_count` | 未結清的 `lent`（我借給別人）欠款筆數 |
| `borrowed_count` | 未結清的 `borrowed`（我向別人借）欠款筆數 |
| `group_count` | 未結清的 `group`（群組分帳）筆數 |

### 2.4 計算邏輯

各欄位的計算方式：

- **`cash_balance`**：沿用現有 `/admin/api/accounting/stats` 的計算邏輯，不重複實作。
- **`receivable`**：篩選 `debts` 資料表中 `debt_type = lent` 且 `is_settled = false` 的記錄，對每筆計算 `amount − paid_amount`，加總所有結果。
- **`payable`**：同上，但篩選 `debt_type = borrowed`。
- **`group_receivable`**：篩選 `debt_type = group` 且 `is_settled = false` 的記錄，對每筆計算成員陣列中 `paid = false` 的 `share` 加總，再加總所有群組。
- **`net_balance`**：最後一步整合計算，以上四個數字都算完後再做加減。

> ⚠ `group` 類型的欠款不計入 `receivable`，而是獨立欄位 `group_receivable`，避免語意混淆。前端可依需求決定是否合併顯示。

### 2.5 邊界情況

| 情況 | 處理方式 |
|------|----------|
| 欠款記錄為空 | `receivable`、`payable`、`group_receivable` 均回傳 0，不報錯 |
| `paid_amount` 超過 `amount` | 不應發生，但若發生則剩餘金額視為 0，不允許出現負數 |
| 資料庫連線失敗 | 回傳 HTTP 500，錯誤訊息與現有端點格式一致 |

## 三、功能二：還款同步寫入現金流

### 3.1 功能說明

現有的還款 API（`POST /admin/api/debts/:id/repay`）只更新欠款記錄，不會在記帳記錄中留下任何痕跡。此功能要求每次還款時，同步在記帳記錄中新增一筆對應的收入或支出，使現金餘額能夠正確反映實際資金流動。

### 3.2 還款方向對應

| 欠款類型 | 記帳類型 |
|----------|----------|
| `lent`（我借給別人，別人還我） | `income`（收入），分類 = 債務收回 |
| `borrowed`（我向別人借，我還別人） | `expense`（支出），分類 = 債務償還 |

### 3.3 新增的記帳記錄欄位

自動新增的記帳記錄需包含以下欄位：

| 欄位 | 值 |
|------|----|
| `type` | 依上表決定（`income` 或 `expense`） |
| `amount` | 本次還款金額 |
| `category` | 債務收回 或 債務償還 |
| `date` | 還款日期，與還款記錄相同 |
| `description` | 自動填入「還款：{對象姓名}」，例如「還款：王小明」 |
| `debt_id` | 關聯的欠款記錄 ID（ObjectId），供未來追溯用 |
| `auto_generated` | 固定值 `true`，標記此記錄為系統自動產生 |

### 3.4 寫入順序與一致性

兩筆寫入（欠款更新 + 記帳新增）必須在同一個資料庫 session 內完成。若其中任一失敗，兩者都必須回滾，不可出現只有其中一筆成功的狀況。

> ⚠ 若系統暫時不支援資料庫 transaction，則採備選方案：先寫欠款、再寫記帳；若記帳寫入失敗，在回傳給前端的錯誤訊息中標注「欠款已更新、記帳未同步」，讓使用者手動補記。

### 3.5 刪除欠款時的處理

當使用者刪除一筆欠款時，由該欠款還款所自動產生的記帳記錄如何處理，需明確定義：

| 選項 | 說明 |
|------|------|
| **【建議】保留記帳記錄** | 記帳記錄上新增欄位 `debt_deleted = true` 作為標記，現金餘額不受影響，歷史資料完整 |
| 連帶刪除記帳記錄 | 現金餘額會回退，歷史記錄消失，不建議，可能讓使用者困惑 |

### 3.6 前端顯示注意事項

- 分類統計頁面中，「債務收回」與「債務償還」這兩個分類應可被識別為特殊分類，顯示時加上標記或不計入一般消費分析。
- 記帳清單中，`auto_generated = true` 的記錄可顯示小圖示或標籤，讓使用者知道這是系統自動產生的，避免困惑。
- 使用者不應能手動修改 `auto_generated` 記錄的 `debt_id` 欄位。

## 四、功能三：群組分帳金額整合

### 4.1 功能說明

群組分帳記錄（`debt_type = group`）目前只儲存每位成員的份額與是否已付款，沒有一個「我目前還能收到多少錢」的計算值。此功能要求在 API 回傳群組欠款時，動態附加此計算欄位，供統計層使用。

### 4.2 新增計算欄位

| 欄位名稱 | 計算方式 |
|----------|----------|
| `pending_receivable` | 成員陣列中，`paid = false` 的所有 `share` 加總 |
| `total_members` | 成員陣列的總人數 |
| `paid_members` | `paid = true` 的成員人數 |

這些欄位為動態計算值，不儲存在資料庫中，每次 API 回傳時即時計算。

### 4.3 套用範圍

- `GET /admin/api/debts`（列表）：每筆 `group` 記錄都附加上述欄位。
- `GET /admin/api/debts/:id`（單筆）：同上。
- `GET /admin/api/stats/overview`（整合統計）：使用 `pending_receivable` 計算 `group_receivable`。

### 4.4 群組結清邏輯

當所有成員的 `paid` 都為 `true` 時，`is_settled` 應自動設為 `true`。此邏輯需加入到「切換成員已付款」的 API 中。

| 操作 | 觸發條件 |
|------|----------|
| 自動結清 | 最後一位 `paid = false` 的成員被標記為已付款時 |
| 自動取消結清 | 已結清的群組中，任一成員的 `paid` 被改回 `false` 時 |

## 五、新增記帳分類

為配合功能二的自動記帳，需在現有的 `ALLOWED_CATEGORIES` 中新增以下兩個分類。這兩個分類建議在前端的分類選擇器中不顯示（不讓使用者手動選），僅供系統內部使用。

| 分類名稱 | 用途 |
|----------|------|
| 債務收回 | `lent` 欠款還款時自動產生的收入記錄所使用的分類 |
| 債務償還 | `borrowed` 欠款還款時自動產生的支出記錄所使用的分類 |

## 六、影響範圍總覽

| 類別 | 需修改 / 新增的內容 |
|------|---------------------|
| 新增 API | `GET /admin/api/stats/overview` |
| 修改 API（後端邏輯） | `POST /admin/api/debts/:id/repay`（加入同步寫記帳） |
| 修改 API（回傳資料） | `GET /admin/api/debts` 與 `GET /admin/api/debts/:id`（加入動態計算欄位） |
| 修改 API（自動結清） | `PUT /admin/api/debts/:id/members/:idx/pay`（加入群組自動結清判斷） |
| 資料庫常數 | `ALLOWED_CATEGORIES` 加入「債務收回」、「債務償還」 |
| 前端統計頁面 | 使用新的 `/stats/overview` 端點，顯示淨餘額、應收、應付 |
| 前端記帳清單 | 自動產生的記錄加上識別標記 |
| 前端分類選擇器 | 隱藏「債務收回」、「債務償還」，不顯示於手動選項中 |

## 七、本次不納入的功能

以下功能不在本規格範圍內，未來可獨立規劃：

- **欠款到期提醒**：需先在 `create_debt` 的 schema 中新增 `due_date` 欄位，並建立排程通知機制。
- **現金流預測圖表**：依欠款到期日繪製預期資金流入/流出，需 `due_date` 欄位。
- **還款的反向操作**：撤銷已記錄的還款，並同步刪除對應的記帳記錄。
